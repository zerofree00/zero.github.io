这次博客搭建很简单，但里面包含了一个完整的小型发布流程：克隆仓库、修改页面、写文章、提交、推送，然后等待 GitHub Pages 构建。

第一步是把仓库拉到本地。仓库使用的是 `gh-pages` 分支，说明它本身就是用来发布静态页面的。根目录里的 `_config.yml` 指定了 `jekyll-theme-slate`，所以不需要从零开始写布局，只要把内容整理成 Markdown，GitHub Pages 就能生成页面。

第二步是写首页。首页的作用不是放很多复杂信息，而是让访问者快速知道这里是什么、有什么文章、从哪里进入。对个人博客来说，清楚比花哨更重要。一个标题、一段说明、几篇文章入口，就足够开始。

第三步是写文章。Jekyll 的文章放在 `_posts/` 目录里，文件名格式通常是 `年-月-日-文章名.md`。文件开头的 front matter 用来声明标题、布局和发布时间。

第四步是处理路径。因为这个仓库是项目页，不是用户主页，所以访问地址里需要带上仓库名：`/zero.github.io/`。很多 GitHub Pages 的链接问题，本质上都是根路径和项目路径没有分清。

最后是提交和推送。每完成一个明确的阶段就提交一次，这样回头看历史时会很清楚：哪次是新增文章，哪次是修复链接，哪次是调整配置。

搭博客不是一件大事，但它很适合练习完整的工程闭环。能把一个小东西从本地交付到线上，本身就是一种很好的手感训练。
