title: "未来日期导致 Jekyll 文章不发布"
date: 2026-04-30 13:10:00 +0800
---

新文章写完之后，首页链接看起来没问题，但点开却是 404。这个问题最后定位到一个很小的原因：文章日期写到了未来。

Jekyll 默认不会发布未来日期的文章。比如今天是 `2026-04-30`，如果文章文件名是 `2026-05-01-something.md`，或者 front matter 里的 `date` 是未来时间，那么 GitHub Pages 构建时就会跳过它。

这类问题很容易误判成链接写错、路径配置错、构建失败，甚至以为 GitHub Pages 没刷新。实际上，文章根本没有进入最终生成的网站目录，所以无论链接怎么点，都会 404。

排查时可以按这个顺序来：

1. 先确认目标 URL 是否返回 404。
2. 再看 `_posts/` 里的文件名日期。
3. 接着检查 front matter 里的 `date`。
4. 最后确认 GitHub Pages 是否已经重新构建。

修复方式也很直接：把文件名和 `date` 改成当前日期或过去日期，然后重新提交推送。

这个坑提醒我，静态站点不是“文件存在就一定能访问”。它中间还有一个构建过程，而构建规则决定了哪些内容会被发布。
